# Design Coder References

Consult these primary sources when the task needs their specific guidance. Project rules and platform requirements remain the authority for product decisions.

- Native HTML behavior and semantics: [WHATWG HTML](https://html.spec.whatwg.org/) and [MDN HTML](https://developer.mozilla.org/en-US/docs/Web/HTML).
- CSS syntax, custom properties, selectors, and pseudo-classes: [MDN CSS reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference), [CSS custom properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Cascading_variables/Using_custom_properties), and [CSS pseudo-classes](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Pseudo-classes).
- Accessible component behavior: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/).
- BEM class architecture: [BEM methodology](https://en.bem.info/methodology/), [naming convention](https://en.bem.info/methodology/naming-convention/), and [BEM CSS](https://en.bem.info/methodology/css/).
- Platform interaction conventions when relevant: [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) and [Material Design 3](https://m3.material.io/).

HTML/CSS can represent visual state but does not prove complete runtime accessibility, keyboard behavior, or application functionality.
