# Design Auditor References

Use primary sources as evidence; project requirements and actual platform constraints determine applicability.

- Accessibility requirements: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [Understanding WCAG](https://www.w3.org/WAI/WCAG22/Understanding/), and [WAI accessibility tutorials](https://www.w3.org/WAI/tutorials/).
- Accessible component patterns: [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/).
- HTML and CSS checking: [WHATWG HTML](https://html.spec.whatwg.org/), [MDN HTML](https://developer.mozilla.org/en-US/docs/Web/HTML), [MDN CSS reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference), and [MDN CSS pseudo-classes](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Pseudo-classes).
- CSS architecture: [BEM methodology](https://en.bem.info/methodology/) and [BEM naming](https://en.bem.info/methodology/naming-convention/).
- Token format: [Design Tokens Format Module 2025.10](https://www.designtokens.org/TR/2025.10/format/). This is the applicable Design Tokens Community Group specification, not a W3C Standard.
- Platform conventions: [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) and [Material Design 3](https://m3.material.io/).

Automated checks cover only implemented assertions. They do not certify complete accessibility, runtime behavior, or platform quality.
