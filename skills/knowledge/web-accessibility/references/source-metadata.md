## Freshness process

1. Re-check the WCAG 2.2 success criteria and understanding pages before changing a verification rule.
2. Re-check APG when its widget pattern, keyboard behavior, or ARIA practice is cited.
3. Verify that a proposed requirement is normative in WCAG, guidance in APG, or a project-specific convention.
4. Record the checked date and update the applicable knowledge instructions if behavior has changed.
5. Manually re-check runtime-only claims; static checks are not a substitute for keyboard or assistive-technology testing.

Do not treat an APG recommendation as a WCAG requirement or assume a static HTML example proves interaction behavior.
